Abstraction is boiling down a complex task, into a simpler idea. It is stripping everything away except for the most essential features/functions. I used the InventoryManager class to deal with the backend logic so the Program class (which handled the UI) didn't have to. EX: Program now just calls manager.SaveInventory(), and doesn't deal with how that actually gets accomplished.
Encapsulation is bundling data and methods into a unit, and then strictly controlling access to that data. I did this by making the _inventoryList private, and the attributes in my base class (item) protected. Now, any other parts of my code that want to interact with those attributes have to do so via the specific methods I designed for that purpose.
inheritance is when a derived class inherits the attributes and behaviors of a base class. I created a base class called Item, which contained some attributes that every item for my inventory needs, and each child class inherited them. Then each child class only had to create a few specific attributes relevant only to them.
Polymorphism is when you have a shared object from a base, and different child classes that are different object types can change the way that object behaves, all while calling the same method. In my program, I defined DisplayItemInfo() and GetStringRepresentation() in my parent class, Item. Then when my manager loops through my List<Item> to display the inventory, it only has to call item.DisplayItemInfo(), and it automatically handles each item according to its correct type.
Overall, my program remains very flexible for future changes, and is completely modular and scalable. I can add a new category of items that needs to be tracked, it would be very simple to do so, and nothing about the core architecture would change.
