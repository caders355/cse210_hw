Version Control is the creator's ultimate safety net and time machine all in one. It tracks new versions, changes, additions, and more to programs/files, all from the same location. One can go back and see previous versions, a history of changes and edits, and even versions created or edited by other people. This can enable a team to collaborate on the same project without interfering in each other's work, keeping the same project up-to-date with the latest changes, and lets someone work on their own branch without changing the original program. 
When a program is an app, service, or something else that many people connect to at one time, updates get pushed to the service to keep the user experience fresh and positive. Sometimes, bugs make it into the program and version control allows a dev to go back to recent code, find the error, start a new branch that fixes the problem, and then send it through as a patch - all while the end-user has an uninterrupted experience. 
A common example of a command would be "git commit". This takes a snapshot of current progress on a program, then saves all the changes along with a message (describing what the updated code added or changed) locally, so you have a checkpoint of your progress.
